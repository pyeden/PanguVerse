# PanguVerse Web 交互重构 · 用户故事 v2

> 触发：使用者反馈「界面操作逻辑不好」。这份文档先解释**为什么不好**，再对标业内成熟产品定新信息架构，
> 最后给出可验收的用户故事。实现契约见 `tasks/web-refactor-spec.md`。

---

## 1. 现状诊断（不是感觉，是结构问题）

| 现象 | 根因 |
| --- | --- |
| 侧栏一眼 7 项（概览/运行/任务/历史/原子/领域包/…），分不清哪些是「业务」哪些是「平台」 | 没有信息层级：把「被测系统」和「框架能力」放在同一层 |
| 想看「coding-log-web 最近好不好」要自己去历史里翻 | **没有「项目」概念**：所有运行是一个大平铺列表，靠人肉记忆区分目标 |
| 运行表单先选「模式」（演示/场景/意图/回归），再填一堆 env | 把**框架内部机制**暴露成用户的第一步；用户的心智是「我要测哪个项目的哪套用例」 |
| 回归库一键跑会把不同目标的用例混着跑，大面积假失败 | 数据模型是扁平池，没有归属；UI 也没做保护 |
| 失败详情信息很全，但看完要退出去再找下一次运行 | 缺少「运行 → 再跑一次 / 改配置重跑」的就地闭环（已有但埋在页尾） |
| 3700 行单文件 app.js，8 个视图互相复用一点逻辑 | 没有视图边界，改一处容易连带崩；重构前先拆结构 |
| 打开就要登录，登录后落到概览，不知道第一步干什么 | 缺少「当前上下文 + 下一步动作」的默认落点 |

## 2. 对标（业内怎么做）

| 参考 | 值得抄的点 | 不抄的 |
| --- | --- | --- |
| **GitHub Actions** | 仓库 → workflow → run 的三级结构；run 详情左侧步骤时间线、右侧日志；状态徽色统一 | 过于面向 CI 的 YAML 编辑 |
| **Jenkins** | Job 列表带「最近一次结果 + 稳定性」；失败趋势一眼可见 | 上古 UI 与插件地狱 |
| **Postman / Bruno** | Collection → Run 的层级；环境（Environment）与集合分离，运行时可切换 | 桌面端复杂度 |
| **Grafana** | 顶部「时间范围 + 过滤器」全局生效；面板即数据 | 图表堆砌（我们暂时不需要） |
| **Linear** | 列表支持快捷筛选、键盘优先、空态有明确下一步 | 项目管理语义 |

**收敛出的原则**：
1. **项目是一等公民**：所有运行、套件、环境都挂在项目下；顶栏永远显示「当前项目」。
2. **业务与平台分层**：项目内的「概览/运行/历史/设置」是主路径；「原子库/领域包/任务模板」收进「平台」二级入口。
3. **默认动作明确**：进项目第一屏就是「最近状态 + 一键跑全部套件」。
4. **就地闭环**：运行详情里能直接「再跑一次」「改配置重跑」「看 AI 总结」，不用回列表。
5. **状态可扫读**：通过/失败/异常用统一的语义色 + 图标 + 文本，不靠颜色单独表意。

## 3. 新信息架构

```
全局
├─ 登录 / 退出 / 当前工作区 / 版本
├─ 项目切换器（左侧项目列表，含最近状态）
└─ 平台（二级）：原子库 · 领域包 · 任务模板 · 关于

项目（当前上下文）
├─ 概览：最近 5 次运行、通过率、失败聚合 Top3、一键「跑全部套件」
├─ 运行：选套件 + 环境（继承项目默认，可覆盖）→ 执行 → 阶段进度
├─ 历史：按「套件 / 状态 / 时间」筛选，分页，行内可见通过率与耗时
└─ 设置：项目名、BASE_URL、默认 env（密钥打码）、套件列表与绑定
```

### 术语对齐（避免继续叫错）

| 我们的词 | 用户心智 | 说明 |
| --- | --- | --- |
| Project 项目 | 被测系统 | 如 `panguverse`、`coding-log-web` |
| Suite 套件 | 一组用例 | 一个 scenario 文件即一个套件 |
| Run 运行 | 一次执行 | 归属 project + suite |
| Task 任务 | 保存的运行配置 | 可一键重跑，不再当成独立实体展示 |

## 4. 用户故事（P0，可验收）

| ID | 故事 | 验收要点 |
| --- | --- | --- |
| **UX-01** | 我打开后能立刻知道「有几个项目、各自最近好不好」 | 首屏是项目列表卡片：名称、最近一次状态、通过率、上次时间、套件数；无项目时有引导创建 |
| **UX-02** | 我能一键创建项目并绑定仓库内已有的套件 | 创建表单：名称 + BASE_URL + 默认 env（密钥显示 `***`）+ 勾选套件；保存后出现在列表 |
| **UX-03** | 进入项目后我第一眼看到「现在该干什么」 | 概览含：最近 5 次运行（状态+通过率）、失败聚合 Top3（按失败类型）、主按钮「跑全部套件」 |
| **UX-04** | 我能在项目内选一个套件跑，不用记 env 键名 | 表单继承项目默认 env，只在我覆盖时显示差异；密钥回显为 `***`，留空即沿用 |
| **UX-05** | 跑完我能立刻看到结果，不用离开页面 | 运行浮层显示阶段进度 → 完成即出现「查看详情」；失败时直接给首个失败用例与原因 |
| **UX-06** | 我在详情页能看懂失败，并能就地重试 | 用例→步骤树；失败步骤显示 message/expected/actual；顶部有「再跑一次」「改配置重跑」「AI 总结」 |
| **UX-07** | 我能按项目和状态筛历史，快速定位问题批次 | 筛选（项目/套件/状态/时间）+ 分页；URL 保留筛选条件，刷新不丢 |
| **UX-08** | 我能看到「全部套件」的总结果，而不是逐条拼 | 批量运行产出一次汇总：套件级通过率、总耗时、失败套件清单，并可下钻 |
| **UX-09** | 我不会再被「混跑不同项目」坑到 | 回归/批量入口只能在同一项目内选择套件；跨项目混跑在 UI 层不可达 |
| **UX-10** | 平台能力还在，但不干扰主路径 | 原子库/领域包收进「平台」，仍可搜索与查看契约；从主路径两次点击内可达 |
| **UX-11** | 手机上也能看状态 | 390px 宽：项目卡纵向排列、历史表转卡片、详情步骤可折叠，无横向滚动 |

### 明确不做（本轮）

项目管理的高级能力（成员/权限）、趋势图表、定时调度 UI、套件在线编辑 YAML、多工作区切换。

## 5. 成功度量

- 从登录到说出「coding-log-web 现在是否健康」的点击次数 ≤ 3。
- 跑「一个项目的全部套件」的点击次数 ≤ 2（不含确认）。
- 失败定位：从历史到看到第一条失败原因 ≤ 2 次点击。
- 跨项目混跑在 UI 上**无法**触发（0 条路径）。
